### Gotchas carried forward
- **Cosine, not L2** — set `configuration={"hnsw":{"space":"cosine"}}` at collection creation (verified chromadb 1.5.9; the legacy `metadata={"hnsw:space":...}` form is deprecated). L2 is the default and the space is locked at creation. Distances come back as cosine ∈[0,2] (0=identical) → `Hit.score = 1 − distance`.
- **Embedding parity** — same model/normalization/prompt both sides; `encode_document()` for chunks, `encode_query()` for queries. ⚠️ **bge-small ships no prompts config**, so `encode_query()` adds nothing by default — `Embedder` registers `config.QUERY_PROMPT` ("Represent this sentence for searching relevant passages: ") so the asymmetric prefix actually fires (verified: doc-vs-query cosine 0.9424). **Don't remove the registration** or the asymmetry silently dies.
- **Metadata on every chunk** — stamp `{product_id, source}` at ingestion; an unlabeled chunk is un-securable (hard error).
- **Chunk size ≤ 512 tokens** (bge-small max sequence) or text is silently truncated at embed time. **Proven the hard way at step 11:** a `chunk_size=1024` sweep arm put **433/444 chunks over the cap** — the text is stored whole (so a golden quote still *resolves*) but the *vector* only encodes the first ~512 tokens, so **resolution ≠ retrieval** and exact hit-rate collapsed 0.625 → 0.125. **Verified at step 4:** tiktoken sizing leaks vs bge's WordPiece count — **2/990 chunks** are 513–520 bge tokens (`detective:…:107`, `:146`) and **accepted** (full text stored; only those 2 vectors drop ~6 tail tokens). `Embedder.count_tokens()` is the real check; airtight fix (if eval ever needs it) = size with bge's own tokenizer.

- **`$in:[]` is REJECTED by chromadb 1.5.9** (`ValueError: Expected where operand value to be a non-empty list`) — so SECURITY.md §3/§5's fail-closed `{"product_id":{"$in":[]}}` snippet will **throw** at step 7, not silently match-nothing. - **Empty-entitlement handling = option (a) + a friendly upsell** (Session 6, locked) — zero/unknown entitlements are caught **before the data layer**: `security.py` raises `NoEntitlementsError(NO_LICENSE_MESSAGE)` (mock "no licenses — purchase at www.my-fake-ass-product.derp"), never an `$in:[]` query (chroma rejects it). Fails closed (no store hit → no leak), avoids the crash, mocks a production gate. Reconciled into SECURITY.md §5/§6 + spec E.1. See the `$in:[]` Gotcha.
- **`security.py` built (Session 7, step 7)** — option (a) implemented to the SECURITY.md §5 reference, plus one hardening: `entitlement_filter` returns `{"$in": list(allowed)}` (a **copy**) so the returned filter holds no live handle to the `ENTITLEMENTS` map — a mutation of the filter can't rewrite authz state for later requests (a silent privilege escalation). `access-control-reviewer` PASS validated this as sound/necessary/zero-downside. - **Eval design realized as ADR-004 (Session 10, step 10)** — golden set anchored to **source quotes** (18 rows, 6/product, `root` user), resolved to live chunk ids at eval time so it survives every re-chunk; a zero-match quote is a **hard error** (typo'd answer key, not a 0 score). `eval.py` **re-chunks from source in-process** (chosen over adding `get_all()` to the `VectorStore` Protocol — keeps the one deliberate abstraction narrow; drift risk mitigated because chunking is deterministic + the chunk count is logged). Four metrics as **pure, unit-tested functions**; run through the **real guarded `Retriever` as `root`** (measures the shipping path, entitlements can't confound quality). **Option 1 (honest baseline)** — the low 0.278 baseline ships as-is (ideal room-to-climb for the step-11 sweep, and it *is* the finding: dense retrieval + 512-token chunks = poor pinpoint/paraphrase recall); **per-tier exact/paraphrase tagging deferred to step 11** when the sweep needs it. See `docs/explainers/evaluation.md`.
- **Per-tier means live in `eval.py`, not a throwaway script (Session 11, step 11, "decision 2a")** — `tier` is a first-class field on `QueryEval`, aggregated by a pure `aggregate(label, rows) -> TierMeans` that's unit-tested (means + count, and empty-slice → zeros not a crash); `EvalReport` exposes `overall` + `by_tier` instead of flat `mean_*`. The tier split turned out to be *the* lens (the overall mean hides that exact and paraphrase want opposite chunk sizes), so it belongs in the harness permanently. Rows without a `tier` key degrade to `"untagged"` rather than erroring.
- **Golden set balanced to 21 rows (Session 11, step 11, "decision 1b")** — 3 verbatim `exact` rows added so the split is 8 exact / 13 paraphrase (was 5/13) and each tier mean rests on enough rows to mean something. All 21 re-verified `|R|=1` at 256/512/1024 before the sweep (`"war of nature"` had to be lengthened to `"from the war of nature, from famine and death"` — the short form matched two chunks). **Consequence: the headline baseline moved 0.278 → 0.333 purely from the row change**, so never compare a post-step-11 number to a pre-step-11 one.
- **512 chunking is now DATA-BACKED, not a default (Session 11, step 11)** — the sweep **disproved** the step-10 "smaller chunks will raise the baseline" hypothesis: at k=5, overall hit-rate **512 (0.333) > 256 (0.286) > 1024 (0.238)**. Chunk size is a **precision/recall trade, not a monotonic dial** — shrinking the chunk also shrinks every competitor's signal and multiplies confusable neighbors. Exact queries want ~512 (0.625), paraphrase queries want *larger* (1024 → 0.538 @k10); there's no single best size, only a best size per query type → the argument for hybrid retrieval / multi-resolution indexing later. Full write-up + numbers: `docs/history/EXP-chunk-size-sweep.md`.

- **The loader seam's two shape decisions (Session 12, step 1, spec-phase-1.5 A.1/A.2)** — **(1) `load(path) -> Iterable[RawDoc]`, not a single doc.** Only the iterable can carry `page`/`row`/`timestamp` provenance natively; text yields exactly one part so the refactor stayed byte-identical; single-return would have forced a breaking Protocol change at step 2/3. The signature **permits** fine granularity without **mandating** it — per-page vs per-file stays a per-loader call, settled by measurement on the eval harness, not by architecture. **(2) Loaders return `RawDoc`, which has no `product_id` field.** ADR-005 said "every loader must stamp `product_id`" — a rule each new loader has to remember; making the return type lack the field means a loader *structurally cannot* forge, drop, or mistype the tag, and `registry.py` becomes the sole `SourceDoc` construction site. Same philosophy as the entitlement filter: structural, not disciplinary. Reviewer verified empirically — a duck-typed loader returning a `product_id`-bearing record had it silently ignored (`Loader` is a `typing.Protocol`, so nothing stops the attempt; nothing reads the field either). Pinned by `_ForgingLoader` in `tests/test_ingest.py`.
